## Concurrencia ejecutada en PostgreSQL real

Cada escenario utilizó dos procesos `psql` y transacciones independientes. Se registraron dos PID de backend distintos y se comprobó el bloqueo real mediante `pg_blocking_pids`, antes de confirmar la primera transacción. No se simularon las respuestas ni se usó PGlite para esta evidencia. Los errores de negocio esperados terminaron la segunda transacción y se comprobaron las filas finales.

| Escenario | Resultado comprobado |
| --- | --- |
| Dos ventas de la última unidad, con cajas distintas | Una venta/pago; la otra `INSUFFICIENT_STOCK`; stock 0 |
| Doble envío de venta con la misma clave | Mismo sale_id; una venta y un descuento de stock |
| Dos ventas contra el último cupo, productos y cajas distintos | Una deuda 100; la otra `CREDIT_LIMIT_EXCEEDED`; el segundo stock intacto |
| Dos abonos de 80 contra deuda 100, cajas distintas | Un abono 80; el otro `AMOUNT_EXCEEDS_DEBT`; saldo 20 |
| Doble envío del abono restante 20 con la misma clave | Mismo receipt_id; un único abono adicional; saldo 0 |
| Dos devoluciones de la misma venta, cajas distintas | Una devolución/reintegro/reposición; la otra `SALE_ALREADY_RETURNED` |
